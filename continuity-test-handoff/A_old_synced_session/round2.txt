## Why Not The Other Three

**deployment readiness under /simulation**: The system IS deployed. It's running right now at `federation-game.deliberatefederation.cloud` with 14 containers, TLS, monitoring, and accessible dashboards. The FEDERATION_REBUILD_CHECKPOINT says to plan deployment readiness for a `/simulation` path, but there's nothing to deploy TO `/simulation` yet — the persistence patch that the checkpoint describes is a phantom. You can't plan rollout of a feature that doesn't exist in production. Deployment readiness comes AFTER the feature is built, not before.

**timeline/history arc integration**: The HistoryArcOrchestrator is the most sophisticated subsystem in the codebase (~1321 LOC, 8 methods including `advance_year()`, `run_simulation()`, `resolve_branch_points()`, `emotional_valence()`, `ideological_polarity()`). But all of this is vaporized on every backend restart. Integrating timeline depth before persistence is like painting a house that has no foundation — the paint is perfect until the first wind blows. The 100-year simulation cannot accumulate state if the runtime is volatile.

**UI/control-plane coherence**: Bridge.html V1.3 (1781 LOC) is already feature-complete for the current depth of simulation. It renders: ship systems, consciousness metrics, policy log, rival radar, faction radar, event cards with choices, comms ticker, animated starfield viewscreen, and failure-state visibility. Adding more UI for features that don't persist is premature — the user would see richer controls but all data behind them is ephemeral. UI coherence should follow data coherence, not lead it.
