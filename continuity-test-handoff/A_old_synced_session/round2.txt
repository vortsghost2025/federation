PRIMARY RISK
============================================================

HistoryArcOrchestrator failure before snapshot restore creates a
MASKED FAILURE on every backend restart.

The chain is:
  1. Main.py creates HistoryArcOrchestrator() + .initialize()
     (try/except — sets self.history_arc = None on any error)
  2. db_manager loads latest snapshot (Postgres row with history_arc_json)
  3. _restore_from_snapshot checks: if arc_json AND self.history_arc
       -> imports arc state
       -> silently skips if self.history_arc is None
  4. all subsequent /history-arc endpoints return 503 "not available"

The trigger: federation_game_history_arc.py imports 4 thin adapter
modules (technology/quest/political/npc integration). If any one
of those raises ImportError — module present but has import bugs,
internal import failures, or an unexpected dependency — the
history arc silently initializes to None.

The current deployment-proof observations (turn 4->1, stability
97->70, year 2391 before the rebuild) may be observing history arc
resets, not just basic game_state resets. Because the save snapshot
serializes history_arc conditional on self.history_arc being
not-None (line 339 in main.py) — a never-restored arc means the
first save creates a NULL history_arc_json column.

This is not just a reset bug. It is a CATASTROPHIC SILENT FAILURE:
the 100-year century arc offers to restart from year 0 every single
restart, and the API endpoint signature (GET /history-arc returns
system_available: false) looks clean and correct — it provides no
hint that persistence BECAUSE of a previous init failure.

DEPLOYMENT READINESS is NOT YET ACHIEVED until this is either:
  (a) Confirmed a non-issue via test (startup diagnostic logging),
  (b) Fixed with a fix package, or
  (c) Explicitly accepted as current acceptable state.
