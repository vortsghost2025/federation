The current version is better as a *debug graph*, but still weak as a **world map**. Circles are okay for “temporary influence radius,” but they are wrong for actual territory because territory should be shaped by:

* where faction members are
* where faction events happen
* explored/claimed systems
* borders with other factions
* contested overlaps
* expansion history

Right now it still reads like:

```text
8 colored bubbles behind a relationship graph
```

It needs to become:

```text
a living territorial map where factions own/influence irregular regions,
and NPC links are a second overlay on top
```

## The fix concept

Do **not** use circles as final territory.

Use circles only as a fallback when there is not enough data.

Better model:

| Data available       | Territory shape                       |
| -------------------- | ------------------------------------- |
| 1 NPC / no history   | small seed circle                     |
| 2 NPCs/events        | capsule / stretched hull              |
| 3+ NPCs/events       | convex hull or soft blob              |
| contested overlap    | outlined/striped overlap zone         |
| explored systems     | territory expands toward those points |
| abandoned/lost areas | faded boundary / former territory     |

The faction border should be computed from **points**, not from a fixed radius.

## Implementation shape

The first good version can be simple:

```text
For each faction:
  points = [homeAnchor, factionNpcPositions, factionEventPositions, exploredPoints]
  if points.length >= 3:
      territory = convexHull(points)
      territory = padded outward by 40–80px
  else:
      territory = fallback circle/capsule
```

That alone will make it feel much more like a real map.

Later, if you want it prettier, the agent can upgrade from:

```text
convex hull
```

to:

```text
concave hull / alpha shape / metaball blob / Voronoi territory
```

But **do not start there**. Convex hull is the right first pass.
