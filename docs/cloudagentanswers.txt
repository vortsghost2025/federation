3. Worker Intelligence (worker.py)
Tick Loop Flow:

Fetches backend health check
Initializes Apprise notifications
Enters main loop with TICK_INTERVAL (default 60s from env)
Calls endpoints in sequence:
/npcs/advance-turn (120s timeout)
/simulation/tick (15s, async with polling)
/political/process-turn (60s)
/history-arc/advance (60s)
/simulation/autonomous/tick (15s, async with polling)
/cognition/tick (120s)
/narrator/generate (90s)
Auto-saves via /state/save
Publishes to Redis federation:updates channel
Checks for significant events and sends notifications
Endpoints Called: All backend simulation endpoints via HTTP POST

Notification Decision Logic:

Fetches crisis readout from /map/data
Checks check_significant_events() for:
Era transitions
Coherence collapse (< 0.3)
Rival hostile actions
Timeline branch points
Chaosbringer activity
Laws passed
Checks check_npc_broadcasts() for NPC events with significance >= 0.5
Builds tiered notifications by crisis classification
Throttle/Dedupe Logic:

STABLE/MODERATE: No Telegram notification
ELEVATED+: Notification sent
10-minute dedupe: Same headline + classification within 10 mins suppressed
Severity increase: Always sends immediately
Uses _last_notification dict to track state

6. Redis Data Model (npc_autonomy.py)
Redis Keys:

npc_thoughts:{char_id} - ZSET (score=timestamp) of recent thoughts
npc_opinion:{char_id}:{player_id} - HASH of opinion data
npc_actions:{char_id} - ZSET (score=timestamp) of recent actions
npc_relationships:{char_id} - HASH of relationship values with other NPCs
npc_world_events - ZSET (score=timestamp) of global events
npc_mood:{char_id} - STRING current mood state
npc_last_active:{char_id} - STRING timestamp of last activity
npc_decisions:{char_id} - ZSET (score=timestamp) of recent decisions
npc_broadcast_events - ZSET for significant NPC broadcasts
npc_profiles - HASH/list of NPC profile data
npc_faction_context:{char_id} - STRING JSON with faction info
Data Structures:

ZSETs: Ordered by timestamp for thoughts, actions, decisions, world events
HASHes: Relationships (NPC-to-NPC scores), opinions, faction context, world state
STRINGs: Mood, last active timestamps, cached thoughts
Key pattern: npc_<data_type>:<char_id> for NPC-specific data

8. Build/Deploy Pipeline
Backend Python Files:

# From project root (S:\federation\federation-game)
docker-compose build backend
docker-compose up -d backend
Uses bind mount /docker/federation-game/backend:/app:ro
Requires docker-compose build then up -d to pick up changes
Worker also uses same image, so rebuild applies to both
Worker Python Files:

# Same as backend - shares image
docker-compose build worker
docker-compose up -d worker
Worker and backend share the same Dockerfile and build context
No separate build needed if backend was rebuilt
Frontend HTML Files:

# HTML files served from bind mount
# Just refresh browser - no build required
docker-compose restart frontend
Files mounted read-only from /docker/federation-game/public_html
Changes to mounted files appear immediately (nginx serves static content)
No rebuild needed - restart is sufficient since it's static HTML served by nginx

=== CORRECTIONS (from local agent discoveries) ===

SECTION 1 CORRECTIONS:
- Backend does NOT need rebuild for Python changes. It has a bind mount (:ro) so
  `docker compose restart backend` picks up file changes immediately.
- Worker has NO bind mount. Code is baked into Docker image at build time.
  Must run `docker compose build worker && docker compose up -d worker` to deploy.
- Frontend: Traefik/Docker caching can serve stale HTML. Always run
  `docker compose restart frontend` after copying new HTML to public_html/.

SECTION 8 CORRECTIONS:
- Backend: `docker compose restart backend` is sufficient (bind mount picks up changes).
  No build needed for Python file changes.
- Worker: MUST build + up. Simple restart does nothing — no bind mount.
  `docker compose build worker && docker compose up -d worker`
- Frontend: Restart IS needed after file changes to public_html/ due to
  Traefik/Docker caching. `docker compose restart frontend`

ADDITIONAL NOTES (not in cloud agent map):
- SCP from Windows strips leading spaces, corrupting Python indentation.
  Use PowerShell base64 encode → SCP b64 file → decode on VPS → py_compile validate.
  (This is the problem Gastown rig + Tailscale SSH solves natively.)
- Traefik priority-200 rule routes specific .html paths to frontend.
  New HTML pages must be added to this rule or backend catches them as 404 JSON.
  Current list: starmap.html, worldguide.html, constellation.html, adult.html,
  index.html, spectator.html, bridge.html, simulation.html
- Telegram bot uses Apprise library internally (not direct Bot API calls).
  URL format: tgram://{bot_token}/{chat_id}/
  Env var: NOTIFICATION_URLS in .env
