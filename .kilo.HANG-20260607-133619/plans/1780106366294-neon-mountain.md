# Plan: Vision-Capable Model Feedback Loop for Starmap Visual QA

**Context:** Federation starmap visual quality is currently assessed by screenshot inspection only. The agent (and user with visual disability) cannot directly observe whether territory fills, labels, NPC markers, and nebula effects are actually rendering correctly. The `/map/data` 404 is also unresolved.

## Goal
Build a closed loop: render screen → vision model sees it → structured critique → code fix → re-render → verify.

---

## Step 1 — Pick the vision model

**Recommended: Gemini 2.0 Flash (already configured via NIM)**
- Already in `nvidia_nim_client.py` as `GEMINI_MODEL` fallback
- Free tier via Google Generative AI API
- Natively multimodal — accepts `image/jpeg` base64 inline

**Alternatives if needed:**
- GPT-4o via OpenRouter (already configured in `npc_autonomy.py`)
- Claude 3.5 Sonnet via Anthropic (vision capable)

Decision: Use Gemini 2.0 Flash first since it's already in the NIM client fallback chain.

---

## Step 2 — Add vision call path to `nvidia_nim_client.py`

Add a new method `call_vision(model, prompt, image_bytes, mime_type)` that:
- Accepts raw image bytes + MIME type
- Builds a `contents` array with `inline_data` part (Gemini format)
- Routes through existing NIM key rotation
- Returns structured text description from the model

This is a read-only addition to the client — no changes to existing call paths.

---

## Step 3 — Create `spatial_qa.py` (new file in backend/)

A lightweight QA script that:
1. Takes a screenshot URL or file path
2. Loads current `buildNodesSpatial` / `buildNodesLegacy` parameters
3. Sends screenshot to Gemini 2.0 Flash with a structured prompt:

```
You are a game UI QA reviewer. Review this starmap screenshot.
Rate 1-5 on:
1. Territory fill visibility — are colored faction regions clearly distinguishable?
2. Label readability — are faction/sector labels legible at this zoom?
3. NPC marker clarity — are NPC dots/icons distinguishable from planet markers?
4. Overall contrast — is there enough contrast between elements and background?
5. Visual clutter — is the map too busy?

For each: score + 1-sentence explanation.
End with top 3 fix priorities.
```

4. Returns structured JSON: `{scores: {...}, priorities: [...], raw_response: "..."}`

---

## Step 4 — Wire into the existing spatial render pipeline

The `simulation.html` server-side render (`/simulation/render`) or the frontend canvas can be triggered to:
1. Render current state to a PNG (canvas → base64 → POST to backend temp path)
2. Call `spatial_qa.py` with the image
3. Store structured critique in a known location (Redis key or file)
4. Surface it via a new API endpoint: `GET /spatial/qa-report`

This means: no frontend changes needed initially. The API endpoint returns the QA report as JSON.

---

## Step 5 — Create the QA loop script

`scripts/starmap_qa_loop.py`:
```
1. Trigger render (curl POST /simulation/tick or direct call)
2. Wait for render to complete
3. Fetch screenshot (curl http://localhost:8080/render.png or similar)
4. Call spatial_qa with screenshot
5. Print structured report
6. Exit with code 0 (report JSON to stdout)
```

This can be run manually: `python scripts/starmap_qa_loop.py > qa_report.json`

## Step 3 (revised) — Screenshot source

**Decision: Headless Puppeteer capture service in Docker**

The maps render as HTML5 Canvas in `starmap.html` and `simulation.html` in the browser. No server-side PNG export exists. Two options:
- **Frontend JS:** add `canvas.toBlob()` → POST to `/spatial/capture`. Requires frontend edits.
- **Headless browser on VPS:** run Puppeteer against the live URL, capture PNG on demand. No frontend changes. Uses the VPS's existing Docker stack.

Choice: Puppeteer capture service. Add a new Docker service to the `federation-game` compose file: `federation-game-capture-1` — lightweight Node.js container, connects to the reverse proxy, exposes `POST /capture` → returns PNG bytes. This is the vision loop's eyes.

## LM Studio — vision model path (revised for accessibility)

The CUDA12 backend fails because Windows DLL loading can't find `ggml-cuda.dll` at runtime. The user has a visual disability and cannot perform Windows environment variable edits. **PATH edits are off the table as a required step.**

### Option A: Switch to Vulkan backend in LM Studio (recommended, zero system changes)
LM Studio already has `llama.cpp-win-x86_64-vulkan-avx2-2.14.0` installed. Switching is a UI-only action:
1. Open LM Studio
2. Settings → Developer → Backend → select **Vulkan** (or CPU)
3. The RTX 5060 supports Vulkan natively — no driver or PATH changes needed

Then download a multimodal vision model that runs on 8GB VRAM:
- **moondream2** (1.7B params, ~1.5GB, runs comfortably on RTX 5060 via Vulkan) — best for this use case, designed for image QA
- **LLaVA 1.6 7B** (~4GB, fits in 8GB VRAM) — more capable but heavier
- **Florence-2** (small variants, Microsoft, strong visual grounding)

### Option B: Skip LM Studio entirely for vision — use NIM API directly
The existing `nvidia_nim_client.py` already has a Gemini 2.0 Flash fallback. Google's Generative AI API is free tier, zero local setup, multimodal:
- No LM Studio fix needed
- No model download needed
- Backend just adds a `call_vision()` method that POSTs image bytes + prompt to Google's API
- `nvidia_nim_client.py` gets a new method, no changes to existing call paths

**Recommendation: Option B** — it's zero friction for the user, uses existing API keys pattern, and the Gemini 2.0 Flash vision capability is genuinely good for UI screenshot critique. LM Studio stays as-is (Vulkan or CPU backend) for local LLM experimentation unrelated to the project.

## LM Studio fix — copy-paste commands (for accessibility)

The user has a visual disability and cannot navigate Windows System Properties UI. These commands can be pasted by a helper, or run if the user has screen-reader accessible terminal.

### Option 1: Add CUDA12 backend to user PATH (one-liner, PowerShell)

Open PowerShell (Win key → type "powershell" → Enter) and paste:
```powershell
$newPath = [Environment]::GetEnvironmentVariable("PATH", "User"); if (-not $newPath.Contains("lmstudio")) { $newPath += ";C:\Users\seand\.lmstudio\extensions\backends\llama.cpp-win-x86_64-nvidia-cuda12-avx2-2.18.0"; [Environment]::SetEnvironmentVariable("PATH", $newPath, "User") }
```

Then close and reopen LM Studio. That's it — no UI navigation required.

### Option 2: Switch LM Studio to Vulkan backend + download a vision model (zero PATH changes)

Once LM Studio opens on Vulkan, search for and download one of these in the model browser:

| Model | Size | VRAM needed | Best for |
|-------|------|-------------|----------|
| **moondream2** | 1.7B params | ~1.5GB | Image QA specifically designed for, fastest, fits 8GB RTX 5060 with room to spare — **top pick for starmap screenshot review** |
| **LLaVA 1.6 7B** | 7B params | ~4GB | General-purpose multimodal, stronger reasoning, more chatty |
| **Florence-2 small** | ~0.2B | ~1GB | Microsoft visual grounding model, excellent at identifying objects and layout in images, very fast |
| **MiniCPM-V 2.5** | ~2.8B | ~2.5GB | Good balance of size and vision quality, Chinese-English bilingual |

**Recommended download for this project:** **moondream2** (1.7B) — it's purpose-built for image question-answering, exactly what a screenshot QA loop needs. Search "moondream2" in LM Studio's models browser, download, then chat with images by clicking the image attach button in the chat bar.

Already covered above — backend just needs a `call_vision()` method. No model download, no GPU, no PATH changes. Fully accessible since it's just API calls.

**Recommendation for this user:** Use a helper to run the PowerShell one-liner (Option 1) if they want local vision inference in LM Studio. Otherwise Option 3 (NIM API) is zero-friction and already has the API key pattern in the codebase.
